## 一、项目概览

| 项 | 说明 |
|----|------|
| 框架 | Vue 3 + Vite 4 |
| 状态管理 | Pinia（含 localStorage 持久化） |
| 3D / 动效 | Three.js（太空银河场景）、Lottie、GLSL 着色器 |
| UI | Element Plus、自定义 SCSS（太空青绿主题） |
| PWA | `vite-plugin-pwa`（自动更新、离线缓存） |
| 产物 | 纯静态文件（输出到 `dist/`），可托管于任意静态服务器 |
| 内置页面 | 相册、随笔、猫猫、**音乐**、**网盘**、**留言板** 等全屏内页 |

> 本项目最终产物是**纯前端静态资源**，不需要 Node 服务常驻；但「音乐」「留言板」依赖外部后端 API（详见[第七节](#七依赖的后端服务)）。

## 三、环境变量配置

1. 首次部署，复制示例文件：
   ```bash
   cp .env.example .env
   ```
2. 编辑 `.env`，填写站点信息、天气 Key、音乐歌单、网盘地址、留言板后端等。
3. 各字段含义见 `.env.example` 内注释；**音乐 / 网盘 / 留言板**的真实数据配置详见 [`docs/数据与环境配置指南.md`](./数据与环境配置指南.md)。

⚠️ **环境变量在构建时被打包进静态产物**。修改 `.env` 后必须：
- 开发环境：重启 `npm run dev`
- 生产环境：重新 `npm run build` 并发布

> Docker 构建时，若镜像内不存在 `.env`，根目录 `Dockerfile` 会自动 `cp .env.example .env`。**生产部署务必提前准备好自己的 `.env`**，否则会用示例占位数据。

## 六、部署方式

### 方式 A：静态托管（Vercel / Netlify / OSS+CDN）

最省心，适合个人站。

**Vercel / Netlify**
- 构建命令：`npm run build`
- 输出目录：`dist`
- 在平台「环境变量」中配置 `.env` 里的所有 `VITE_*` 变量（平台不会读取仓库里的 `.env`）。
- SPA 回退：本项目为单页应用，需将所有未命中路由回退到 `index.html`。
  - Netlify：新增 `public/_redirects` 内容 `/*    /index.html   200`
  - Vercel：通常自动处理；如需可加 `vercel.json` 的 rewrites。

**对象存储 + CDN（如阿里云 OSS、七牛、COS）**
- 上传 `dist/` 全部文件。
- 开启「静态网站托管」，默认首页与 404 页均设为 `index.html`（SPA 回退）。
- 配置 CDN 加速与 HTTPS 证书。

---

### 方式 B：Docker（自带 http-server，最快上手）

仓库根目录的 `Dockerfile` 是**自包含**的：在镜像内完成 `npm install` 与 `npm run build`，再用 `http-server` 提供服务（端口 **12445**）。

```bash
# 构建镜像
docker build -t home-app .

# 运行容器（宿主机 8080 -> 容器 12445）
docker run -d -p 8080:12445 --name home-app home-app
```

或使用 `docker-compose.yml`：

```bash
docker compose up -d   # 暴露 12445:12445
```

> 提示：根目录 Dockerfile 在镜像里构建，会使用镜像内的 `.env`（若缺失则复制 `.env.example`）。要用你自己的配置，请确保构建上下文中已有正确的 `.env`。

---

### 方式 C：Nginx 镜像（推荐自建服务器）

`k8s/` 目录提供了基于 **Nginx** 的镜像方案，性能更好、带 gzip / 缓存 / 安全头 / SPA 回退配置（见 `k8s/nginx.conf`）。

该方案要求**先在本地构建好 `dist/`**，再打包进镜像：

```bash
# 1. 在项目根目录构建
npm run build

# 2. 进入 k8s 目录，用脚本打包镜像
cd k8s
bash build.sh          # 会把 ../dist 与 Dockerfile、nginx.conf 一起构建为 guoqiangqi/home-app:latest
```

`build.sh` 等价于：

```bash
mkdir -p temp-build && cp -r ../dist temp-build/ && cp Dockerfile nginx.conf temp-build/
docker build -t guoqiangqi/home-app:latest temp-build/
rm -rf temp-build
```

直接运行该镜像（Nginx 监听 80）：

```bash
docker run -d -p 80:80 --name home-app guoqiangqi/home-app:latest
```

> 如需自定义镜像名，改 `build.sh` 与 `k8s/deployment.yaml` 中的 `image` 字段，并推送到你自己的镜像仓库。

---

### 方式 D：Kubernetes

`k8s/` 目录包含完整清单：`deployment.yaml`、`service.yaml`、`ingress.yaml`，以及脚本 `build.sh` / `deploy.sh` / `cleanup.sh`。

**资源说明**

| 文件 | 作用 |
|------|------|
| `deployment.yaml` | 2 副本，镜像 `guoqiangqi/home-app:latest`，容器端口 80，含存活/就绪探针与资源限制 |
| `service.yaml` | `ClusterIP` Service，端口 80 |
| `ingress.yaml` | nginx-ingress + cert-manager 自动签发 TLS，域名默认 `qicheng.love` |

**部署步骤**

```bash
# 1. 构建并推送镜像（先 npm run build）
cd k8s
bash build.sh
docker push guoqiangqi/home-app:latest   # 推送到你有权限的仓库

# 2. 按需修改 ingress.yaml 中的 host（qicheng.love -> 你的域名）
#    及 deployment.yaml 中的 image（改成你自己的镜像）

# 3. 一键部署（脚本会创建 home-app 命名空间并 apply 全部清单）
bash deploy.sh
```

`deploy.sh` 实际执行：

```bash
kubectl get namespace home-app || kubectl create namespace home-app
kubectl -n home-app apply -f deployment.yaml
kubectl -n home-app apply -f service.yaml
kubectl -n home-app apply -f ingress.yaml
kubectl -n home-app wait --for=condition=ready pod -l app=home-app --timeout=300s
```

**前置条件**
- 集群已安装 **nginx-ingress-controller**。
- 如需自动 HTTPS：已安装 **cert-manager** 且存在名为 `letsencrypt-dns01` 的 `ClusterIssuer`（见 `ingress.yaml` 注解）。否则可注释掉 `cert-manager` 注解与 `tls` 段，改用自有证书 Secret。

**查看与清理**

```bash
kubectl -n home-app get pods,svc,ingress
bash cleanup.sh    # 卸载本项目相关资源
```

> ⚠️ 因为环境变量在构建期注入，**更换 `.env` 后必须重新执行 `npm run build` → `build.sh` → 推送镜像 → 滚动更新**，仅重启 Pod 不会改变已打包的配置。

## 八、域名、HTTPS 与 CDN

- **域名解析**：将域名 A/AAAA 记录指向服务器 IP（自建）或按平台要求配置 CNAME（托管平台）。
- **HTTPS**：
  - 静态平台（Vercel/Netlify/OSS）通常一键签发免费证书。
  - 自建 Nginx：用 Certbot 或在前置网关签发证书。
  - K8s：由 `ingress.yaml` + cert-manager 自动签发。
- **CDN**：建议为静态资源开启 CDN；`nginx.conf` 已对 js/css/图片/字体设置 `Cache-Control: public, immutable`（一年），并对 `sw.js`/`workbox-*.js` 设置 `no-cache` 以保证 PWA 更新及时。

## 九、常见问题

**Q1：改了 `.env` 没生效？**
环境变量在构建期注入。开发环境重启 `npm run dev`；生产环境必须重新 `npm run build`（Docker/K8s 还需重建并推送镜像）。

**Q2：音乐不出声 / 歌单为空？**
`VITE_SONG_ID` 仍是占位值（如 `1111111`），或公共 Meting API 限流。换成真实歌单 ID 并自建 Meting API。详见数据配置指南「音乐页」。

**Q3：留言发出去但看不到 / 进不了自己的库？**
`VITE_TWIKOO_ENVID` 仍为演示后端。请部署自己的 Twikoo 后端并填入。详见数据配置指南「留言板」。

**Q4：刷新页面或直接访问子路径 404？**
未配置 SPA 回退。需将所有路由回退到 `index.html`（Nginx 用 `try_files $uri $uri/ /index.html;`，已在 `k8s/nginx.conf` 配置；静态平台见方式 A）。

**Q5：K8s Pod 起不来 / 镜像拉取失败？**
确认镜像已推送到可访问的仓库，且 `deployment.yaml` 的 `image` 与之一致；私有仓库需配置 `imagePullSecrets`。

**Q6：PWA 缓存导致更新不及时？**
项目使用 `autoUpdate` + `skipWaiting`，配合 `sw.js` 的 `no-cache` 头，通常刷新两次即可更新；如仍异常，可在浏览器开发者工具 Application → Service Workers 中 Unregister 后强刷。
