# 音乐 · 网盘 · 留言板 —— 真实数据与环境配置指南

本文档说明如何把「音乐」「网盘」「留言板」三个页面从内置的**演示/占位数据**切换为**你自己的真实数据与服务**。

> 改动配置后：开发环境（`npm run dev`）会自动热更新；修改 `.env` 后需**重启**开发服务器；生产环境需重新执行 `npm run build` 并部署。

## 一、音乐页

音乐页（`src/views/Music/index.vue`）通过 **Meting API** 拉取歌单，底层组件为 `src/components/Player.vue`（APlayer）。

### 1.1 现状

`.env` 中当前为占位 ID，歌单无法正确加载：

```ini
VITE_SONG_ID = "1111111"   # ← 占位假数据
```

### 1.2 配置真实歌单

编辑根目录 `.env` 文件中以下四个变量：

```ini
# 歌曲 API 地址（Meting API 服务）
VITE_SONG_API = "https://api.wuenci.com/meting/api/"
# 歌曲服务器：netease(网易云) | tencent(QQ音乐)
VITE_SONG_SERVER = "netease"
# 播放类型：song | playlist | album | search | artist
VITE_SONG_TYPE = "playlist"
# 歌单 / 歌曲 ID（见下方获取方式）
VITE_SONG_ID = "你的真实歌单ID"
```

**如何获取歌单 ID：**

- **网易云**：打开歌单网页版，地址形如
  `https://music.163.com/#/playlist?id=`**`7452421335`**，末尾数字即 ID。
- **QQ 音乐**：歌单地址形如
  `https://y.qq.com/n/ryqq/playlist/`**`xxxxxx`**，末尾数字即 ID（QQ 音乐歌单建议不超过 50 首）。

> 若 `VITE_SONG_TYPE = "song"`，则 `VITE_SONG_ID` 填单曲 ID。

### 1.3 关于 Meting API（重要）

`VITE_SONG_API` 指向的公共服务可能限流或失效，**强烈建议自建**：

- 部署文档：<https://github.com/xizeyoupan/Meting-API>（支持 Deno Deploy / Vercel / 服务器）
- 部署后把 `VITE_SONG_API` 改为你自己的地址，例如 `https://your-meting.deno.dev/api`。

### 1.4 不需要音乐？

把 `VITE_SONG_ID` 设为空字符串即可隐藏功能区的迷你播放器：

```ini
VITE_SONG_ID = ""
```

## 二、网盘页

网盘页（`src/views/Pan/index.vue`）的文件列表、存储容量、空间站信息**全部来自配置文件**，不再硬编码。

### 2.1 配置入口

文件：**`src/assets/panFiles.json`**

```jsonc
{
  "link": "https://pan.qicheng.love/",   // 网盘主地址（被 VITE_PAN_URL 覆盖，见下）
  "stationName": "QC · 数据空间站",        // 顶部空间站名称
  "totalSpace": 1024,                      // 总容量（GB，仅用于环形图展示）
  "usedSpace": 386,                        // 已用容量（GB）
  "nodes": 3,                              // 同步节点数（展示用）
  "uptime": "99.9",                        // 在线率（展示用）
  "files": [
    {
      "name": "星图集·银河旋臂.pdf",   // 文件名（后缀决定图标上的 PDF/ZIP 字样）
      "desc": "高清星系结构图鉴合集",    // 一句话描述
      "size": "48.2 MB",                // 大小（纯文本，随意填）
      "date": "2024-12-08",             // 日期
      "type": "doc",                    // 分类，见下方枚举
      "link": ""                        // 该文件的直链/分享链接，留空则跳转到网盘主地址
    }
  ]
}
```

**`type` 可选值**（决定分类筛选与图标配色）：

| type | 分类 |
|------|------|
| `doc` | 文档 |
| `image` | 图片 |
| `video` | 视频 |
| `audio` | 音乐 |
| `archive` | 压缩包 |
| `app` | 应用 |

> 分类标签会自动统计每类数量；某类没有文件时点击会显示空状态。

### 2.2 配置网盘主地址

「进入完整网盘空间」按钮、以及未单独填写 `link` 的文件，都会跳转到网盘主地址。优先级：

```
VITE_PAN_URL（.env） > panFiles.json 的 link 字段
```

在 `.env` 中设置：

```ini
VITE_PAN_URL = "https://pan.qicheng.love/"
```

### 2.3 进阶：对接真实网盘后端

当前页面是「展示 + 跳转」形态。若希望**动态读取真实文件列表**，推荐对接 [Alist](https://alist.nn.ci/)：

1. 部署 Alist 并开启 API（`/api/fs/list`）。
2. 在 `src/views/Pan/index.vue` 中，把 `files` 的来源由静态 JSON 改为接口请求，例如：

```js
import { ref, onMounted } from "vue";
const files = ref([]);

onMounted(async () => {
  const res = await fetch("https://你的alist域名/api/fs/list", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ path: "/", page: 1, per_page: 50 }),
  });
  const json = await res.json();
  files.value = (json.data?.content || []).map((it) => ({
    name: it.name,
    desc: it.is_dir ? "文件夹" : "文件",
    size: formatSize(it.size),       // 自行实现字节转可读大小
    date: (it.modified || "").slice(0, 10),
    type: guessType(it.name),        // 按扩展名映射到上面的 type 枚举
    link: `https://你的alist域名/#${encodeURIComponent("/" + it.name)}`,
  }));
});
```

> 也可对接 WebDAV、对象存储（OSS/S3）等，思路一致：拉取列表 → 映射成上面的字段结构。

## 三、留言板

留言板（`src/views/MessageBoard/index.vue`）使用 [Twikoo](https://twikoo.js.org/) 评论系统，配置在 `src/config/twikoo.js`。

### 3.1 现状

`envId` 当前指向一个演示后端，**评论不会进入你自己的数据库**：

```js
envId: import.meta.env.VITE_TWIKOO_ENVID || 'https://twikoo-one-brown-59.vercel.app'
```

### 3.2 部署你自己的 Twikoo 后端

Twikoo 需要一个后端 + 一个 MongoDB 数据库。任选一种部署方式：

**方式 A：Vercel（推荐，免费）**

1. 准备一个 [MongoDB Atlas](https://www.mongodb.com/atlas) 免费数据库，拿到连接串 `MONGODB_URI`。
2. 按官方教程一键部署到 Vercel：<https://twikoo.js.org/backend.html#vercel-部署>
3. 在 Vercel 项目环境变量里填入 `MONGODB_URI`。
4. 部署完成后得到访问地址，例如 `https://your-twikoo.vercel.app`。

**方式 B：腾讯云环境（CloudBase）**
   得到的是一个**环境 ID**（形如 `your-env-xxxxx`），同样填入下方变量。

**方式 C：Docker 自托管**
   见 <https://twikoo.js.org/backend.html#docker-部署>，得到形如 `https://your-domain/` 的地址。

### 3.3 填写环境 ID

在 `.env` 中：

```ini
# 填你自己的后端地址或腾讯云环境 ID
VITE_TWIKOO_ENVID = "https://your-twikoo.vercel.app"
```

### 3.4 管理评论

首次访问留言板，在评论框点击右上角设置 → 注册管理员密码，即可进入后台管理评论、配置邮件通知、垃圾评论拦截等。

> 评论框的占位文案、字数限制等可在 `src/config/twikoo.js` 的 `twikooConfig.comment` 中调整；评论区配色样式在同文件的 `twikooStyles` 中（已适配太空青绿主题）。

## 四、环境变量速查表

在根目录 `.env` 中配置（参考 `.env.example`）：

| 变量 | 用途 | 示例 |
|------|------|------|
| `VITE_SONG_API` | Meting API 地址 | `https://your-meting.deno.dev/api` |
| `VITE_SONG_SERVER` | 音乐平台 | `netease` / `tencent` |
| `VITE_SONG_TYPE` | 资源类型 | `playlist` / `song` … |
| `VITE_SONG_ID` | 歌单/歌曲 ID | `7452421335` |
| `VITE_PAN_URL` | 网盘主地址 | `https://pan.example.com/` |
| `VITE_TWIKOO_ENVID` | Twikoo 后端地址/环境 ID | `https://your-twikoo.vercel.app` |

非环境变量的数据文件：

| 文件 | 用途 |
|------|------|
| `src/assets/panFiles.json` | 网盘文件列表、容量、空间站信息 |
| `src/config/twikoo.js` | Twikoo 配置与评论区样式 |
| `src/assets/siteLinks.json` | 首页「网站列表」菜单项（音乐/网盘等入口） |

## 五、常见问题

**Q1：改了 `.env` 没生效？**
`.env` 在构建期注入，修改后需**重启** `npm run dev`；生产环境需重新 `npm run build`。

**Q2：音乐页歌单空白 / 加载失败？**
多为 `VITE_SONG_API` 公共服务限流或 `VITE_SONG_ID` 无效。请自建 Meting API，并确认歌单为公开状态。打开浏览器控制台查看网络请求返回。

**Q3：留言板一直转圈或报「信号中断」？**
检查 `VITE_TWIKOO_ENVID` 是否填写正确、后端是否正常、MongoDB 连接串是否有效；后端跨域需允许你的站点域名。

**Q4：网盘文件点击没反应 / 跳错地址？**
确认 `panFiles.json` 中该文件 `link` 是否填写；未填则跳转 `VITE_PAN_URL`（或 JSON 的 `link`）。

**Q5：想隐藏某个入口？**
在 `src/assets/siteLinks.json` 中删除对应项即可（音乐、网盘、留言板等菜单由该文件驱动）。
