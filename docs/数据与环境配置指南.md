# 音乐 / 网盘 / 留言板 —— 真实数据与环境配置指南

本文档说明如何把「音乐」「网盘」「留言板」三个页面从内置的演示（占位）数据切换为你自己的真实数据与后端环境。

> 配置改动主要集中在三处：
> 1. 根目录 `.env`（环境变量）
> 2. `src/assets/panFiles.json`（网盘文件清单）
> 3. 你自行部署的后端服务（Meting API、Twikoo）
>
> ⚠️ 修改 `.env` 后必须**重启开发服务器**（`npm run dev`）或**重新构建**（`npm run build`）才会生效，Vite 不会热更新环境变量。

## 一、音乐页

### 现状

音乐页通过 **Meting API** 拉取歌单。当前 `.env` 中 `VITE_SONG_ID = "1111111"` 是占位 ID，所以歌单为空 / 加载失败。换成真实歌单 ID 即可播放真实歌曲。

### 涉及配置（`.env`）

```ini
# 歌曲 API 地址（Meting API 服务地址）
VITE_SONG_API = "https://api.wuenci.com/meting/api/"
# 歌曲服务器：netease-网易云, tencent-QQ音乐
VITE_SONG_SERVER = "netease"
# 播放类型：song-单曲, playlist-歌单, album-专辑, search-搜索, artist-艺术家
VITE_SONG_TYPE = "playlist"
# 歌单 / 歌曲 ID（留空则不加载播放器）
VITE_SONG_ID = "你的真实歌单ID"
```

### 如何获取真实歌单 ID

- **网易云音乐**：打开歌单网页版，链接形如
  `https://music.163.com/#/playlist?id=123456789`，其中 `123456789` 即为 `VITE_SONG_ID`。
  同时设 `VITE_SONG_SERVER = "netease"`、`VITE_SONG_TYPE = "playlist"`。
- **QQ 音乐**：歌单链接形如
  `https://y.qq.com/n/ryqq/playlist/987654321`，取 `987654321`。
  设 `VITE_SONG_SERVER = "tencent"`。QQ 音乐歌单**建议不超过 50 首**，否则容易超时。
- 想只放单曲：把 `VITE_SONG_TYPE` 改为 `song`，`VITE_SONG_ID` 填单曲 ID。

### 关于 Meting API（重要）

`VITE_SONG_API` 指向的是一个公共/自建的 Meting 服务，用于解析歌曲真实播放地址。公共服务经常限流或失效，**强烈建议自行部署**：

1. 项目地址：<https://github.com/xizeyoupan/Meting-API>
2. 可部署到 Deno Deploy / Vercel / 自己的服务器。
3. 部署完成后，把得到的接口地址（通常以 `/api` 结尾）填入 `VITE_SONG_API`。

> 解析逻辑见 `src/api/index.js` 的 `getPlayerList()`，会自动处理网易云/QQ 两种返回格式，一般无需改动。

## 二、网盘页

### 现状

网盘页的**文件列表、存储容量、节点数**等均来自配置文件 `src/assets/panFiles.json`（已外置，方便维护），其中是一批演示数据。页面底部「进入完整网盘空间」按钮与每个文件默认跳转到你的真实网盘地址。

### 方式 A：作为「真实网盘的展示门户」（推荐，最简单）

适合你已经有一个独立网盘（如 Alist、Cloudreve、坚果云等）的场景：本页面作为精选入口 + 跳转门户。

1. 在 `.env` 设置真实网盘地址：
   ```ini
   VITE_PAN_URL = "https://你的网盘域名/"
   ```
   （留空则使用 `panFiles.json` 里的 `link` 字段）

2. 编辑 `src/assets/panFiles.json`，填入真实展示信息：
   ```json
   {
     "link": "https://你的网盘域名/",
     "stationName": "我的数据空间站",
     "totalSpace": 1024,
     "usedSpace": 386,
     "nodes": 3,
     "uptime": "99.9",
     "files": [
       {
         "name": "示例文件.pdf",
         "desc": "文件简介",
         "size": "48.2 MB",
         "date": "2024-12-08",
         "type": "doc",
         "link": "https://你的网盘/直链或分享链接"
       }
     ]
   }
   ```

   字段说明：

   | 字段 | 含义 | 说明 |
   |------|------|------|
   | `link` | 网盘主地址 | 被 `.env` 的 `VITE_PAN_URL` 覆盖（若已设置） |
   | `stationName` | 空间站名称 | 顶部展示 |
   | `totalSpace` / `usedSpace` | 总容量 / 已用（GB） | 用于容量环与进度条计算 |
   | `nodes` | 同步节点数 | 纯展示 |
   | `uptime` | 在线率 | 纯展示，字符串 |
   | `files[].name` | 文件名 | **后缀决定文件图标标签**（如 `.pdf` 显示 `PDF`） |
   | `files[].desc` | 文件简介 | |
   | `files[].size` / `date` | 大小 / 日期 | 纯展示文本 |
   | `files[].type` | 分类 | 必须是下表中的值，用于分类筛选与配色 |
   | `files[].link` | 该文件的下载/分享链接 | 留空 `""` 则点击跳转到网盘主地址 |

   `type` 允许的值：`doc`（文档）、`image`（图片）、`video`（视频）、`audio`（音乐）、`archive`（压缩包）、`app`（应用）。其它值会落到默认配色。

### 方式 B：对接真实网盘 API（动态拉取文件列表）

适合希望文件列表自动同步、无需手动维护的场景。以 **Alist** 为例（其提供 `POST /api/fs/list` 接口）：

1. 在 `src/api/index.js` 新增一个获取文件列表的函数，例如：
   ```js
   // 获取 Alist 目录文件列表
   export const getPanList = async (path = "/") => {
     const res = await fetch(`${import.meta.env.VITE_PAN_API}/api/fs/list`, {
       method: "POST",
       headers: { "Content-Type": "application/json" },
       body: JSON.stringify({ path, page: 1, per_page: 100, refresh: false }),
     });
     const data = await res.json();
     // 将 Alist 返回结构映射为页面所需字段
     return (data?.data?.content || []).map((f) => ({
       name: f.name,
       desc: f.is_dir ? "文件夹" : "",
       size: formatSize(f.size),       // 自行实现大小格式化
       date: f.modified?.slice(0, 10),
       type: guessType(f.name),        // 自行实现按后缀归类
       link: `${import.meta.env.VITE_PAN_URL}#${path}${f.name}`,
     }));
   };
   ```
2. 在 `.env` 增加 `VITE_PAN_API = "https://你的alist域名"`。
3. 在 `src/views/Pan/index.vue` 中把
   ```js
   const files = ref(panConfig.files || []);
   ```
   改为在 `onMounted` 里调用 `getPanList()` 并赋值，同时处理加载/失败态。

> 不同网盘（Cloudreve、OneIndex、WebDAV 等）接口不同，按其文档实现映射即可，UI 部分无需改动。

## 三、留言板

### 现状

留言板使用 **Twikoo** 评论系统。`src/config/twikoo.js` 的 `envId` 现已支持读取环境变量 `VITE_TWIKOO_ENVID`，默认值是一个演示后端——**评论不会进入你自己的数据库**。需部署你自己的 Twikoo 后端并填入 `envId`。

### 步骤 1：部署 Twikoo 后端

Twikoo 需要一个后端服务 + MongoDB 数据库。官方文档：<https://twikoo.js.org/>。常见方案：

- **Vercel + MongoDB Atlas（免费，推荐）**
  1. 注册 [MongoDB Atlas](https://www.mongodb.com/atlas)，创建免费集群，获取连接字符串 `MONGODB_URI`。
  2. 按官方指引一键部署 Twikoo 到 [Vercel](https://vercel.com/)（[Vercel 部署文档](https://twikoo.js.org/backend.html#vercel)）。
  3. 在 Vercel 项目的环境变量中填入 `MONGODB_URI`。
  4. 部署成功后得到访问地址，如 `https://your-twikoo.vercel.app`。
- **腾讯云云开发（CloudBase）**：得到的是「环境 ID」字符串（而非网址），同样填入 `envId` 即可。
- **Docker 私有部署**：见官方 [私有部署文档](https://twikoo.js.org/backend.html#docker)。

### 步骤 2：填入环境变量（`.env`）

```ini
# 你自己部署的 Twikoo 后端地址，或腾讯云环境 ID
VITE_TWIKOO_ENVID = "https://your-twikoo.vercel.app"
```

### 步骤 3（可选）：进入管理面板

部署后首次在留言板页面右上角点击「设置」图标设置管理员密码，即可管理评论、配置邮件通知、垃圾过滤（Akismet）、内容审核等。详见 <https://twikoo.js.org/config.html>。

> 评论样式（深色玻璃态太空主题）已在 `src/config/twikoo.js` 的 `twikooStyles` 中定义，一般无需改动。前端加载的 Twikoo 脚本版本为 `1.6.44`，如需升级可在 `src/views/MessageBoard/index.vue` 与 `twikoo.js` 中同步修改 CDN 版本号。

## 四、改动生效方式

1. 复制并编辑环境变量文件（首次）：
   ```bash
   cp .env.example .env   # 若还没有 .env
   ```
   然后按上文修改 `.env` 中对应字段。
2. 本地开发：**重启**开发服务器使环境变量生效：
   ```bash
   npm run dev
   ```
3. 生产部署：重新构建并发布 `dist/`：
   ```bash
   npm run build
   ```

> `src/assets/panFiles.json` 属于源码资源，修改后开发环境会热更新；生产环境需重新 `npm run build`。
